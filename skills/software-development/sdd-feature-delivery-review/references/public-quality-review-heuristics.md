# Public-quality review heuristics

Reusable checks for strict Next.js public-surface reviews. Keep these separate from runtime-hardening acceptance when the project has split specs.

## Environment-sensitive metadata tests

Metadata objects are evaluated at module import. A test that imports `metadata` before stubbing `process.env.NEXT_PUBLIC_APP_URL` can pass locally and fail in CI. Verify both modes:

```bash
npm run test -- src/test/public-metadata.test.ts
NEXT_PUBLIC_APP_URL=https://ci.example npm run test -- src/test/public-metadata.test.ts
```

The second run must pass. Prefer `vi.stubEnv`/`vi.unstubAllEnvs` before a dynamic import, or explicitly unset the variable in test setup before importing fallback metadata.

## Generated OG assets

Do not stop at `file public/og.png` and `1200x630`. Inspect the rendered image and, when generated by code, compare text bounding boxes to the canvas and any decorative frame. A common defect is calculating `tagline_w` but drawing at a fixed x-coordinate, causing text to overlap or exceed a border. Check safe margins, contrast, legibility, and whether all text survives social-preview cropping.

## Baseline provenance

A baseline log is evidence only if its status, dependency state, build mode, and HTTP probes predate the implementation. If its `git status` contains the final changed/untracked files, label it invalid/stale; do not use its passing test count as a before/after comparison. Regenerate from a clean tree or document the exact pre-existing worktree state.

## Standalone production verification

Next projects with `output: 'standalone'` should be verified with the actual runtime:

```bash
NEXT_PUBLIC_APP_URL=https://staging.example npm run build
PORT=3100 node .next/standalone/server.js
```

Alternatively build with `VERCEL=1` and use `next start`. Treat the `next start does not work with output: standalone` warning as a limitation of the evidence, not as proof that the deployment runtime is healthy.

## Source-map distinction

Inspect both generated artifacts and HTTP reachability. `.next/server/**/*.map` may exist for server debugging without being public. The required check is that every client `/_next/static/**/*.js.map` URL returns 404/blocked in the production runtime. A couple of guessed URLs are not enough; enumerate actual public chunks, then probe them. Also verify the Docker/Vercel artifact, not only a local development `.next` directory.

## Split-spec reporting

For a public/SEO spec, report metadata, 404, OG, JSON-LD, robots, sitemap, llms, privacy, and indexability. Report `X-Powered-By`, `/api/seed`, browser-console automation, source-map policy, and bundle budgets as separate runtime-hardening follow-ups when that is how the project is scoped. State observed current behavior and missing evidence without silently passing or incorrectly failing the first spec.
